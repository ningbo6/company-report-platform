# 公网只读、内网管理

两个服务共享原 data，保留企业固定编号和二维码地址：

| 用途 | 宿主机应用端口 | Nginx 入口示例 |
|---|---|---|
| 公网报告和 PDF | 127.0.0.1:18888（public） | https://reports.example.org/d/0001/ |
| 内网目录与管理 | 127.0.0.1:18889（app） | https://reports-admin.internal.example.org:8443/admin/ |

所有域名、内网 IP、网段和证书路径均须替换为实际值。

## 部署

1. 迁移完整 data、.env 和素材，保留数据库及编号，不重新初始化。Docker Compose 需 2.24.4 或更新版本（支持 !override）。
2. .env 设置 BASE_URL=https://实际公网域名、COOKIE_SECURE=true。保留 HTTP_PORT=18889、PUBLIC_HTTP_PORT=18888；不将应用端口绑定公网或所有网卡。
3. 执行 `docker compose config --quiet`，再执行 `docker compose up -d --build --wait`。app 先初始化数据库，public 随后启动，不执行启动清理以免影响上传。
4. 宿主机 Nginx 安装 nginx.conf.example，替换公网域名、证书。公网仅转发到 18888。
5. 安装 nginx-admin.conf.example：将 10.20.0.10 替换为服务器实际内网接口 IP，10.20.0.0/24 替换为获准管理的办公网或 VPN 网段，替换管理域名与证书。内网 DNS 解析到该 IP，证书须受管理设备信任。只绑定内网 IP 的 8443，不允许改为通配监听。
6. 防火墙/安全组：公网只放行 80/443；内网 8443 仅允许管理网段；18889/18888 不对外放行。禁止公网负载均衡、穿透或端口转发指向管理入口。
7. 执行 `nginx -t`，成功后重载；通过内网 URL 登录管理台。后台继续要求账号密码和 CSRF 校验。

公开服务允许只读查询页 /（支持 ?q=企业名称或编号）、企业详情、PDF 和 style.css；仅允许读取请求。管理接口、二维码生成、健康信息及未知路径返回 404；公开服务不解析管理会话，Nginx 也剥离 Cookie。公开查询页只显示企业名称、报告页数/大小、更新时间、查看与下载入口；不显示新增、编辑、删除或后台入口。报告详情可返回查询页。即使带入内网管理员 Cookie，公网查询仍为只读。公网有限流和并发限制，public 容器限制 CPU、内存、进程。管理上传上限仍为 1 GB。

二维码 BASE_URL 始终使用公网域名；内网管理域名无需写入 BASE_URL。批量导出只生成企业码，不再生成总目录码，旧企业码保持有效，旧总目录码不适用于公网。

不要将 objects/、.env、backups/ 映射为静态目录。下载仍经过应用，以保留下架检查和 Range 支持。前置 CDN 时需先配置可信 real_ip 来源，不直接信任访客转发头。

## 验收

- 公网：报告页、PDF 下载、HEAD、Range 正常；根目录查询可用；/admin/、/admin/login、/healthz、二维码生成及 POST 不可用。伪造 Host、X-Forwarded-For 也不能进入后台。
- 内网：登录、上传、替换、二维码导出、下架正常；下架后的公网 PDF 返回 410。
- 非授权网段：管理 8443 无法访问；外部 18889/18888 无法访问。
- 运行 verify-origin，核对公网企业页响应中的实例标识；最后用手机移动网络扫描企业固定码。

代码和本地测试不代替服务器实际访问验收。尚未提供服务器、网段、域名和证书时，本目录仅为待配置的部署模板。

本地预览：公开查询 http://127.0.0.1:18888/；内网查询 http://127.0.0.1:18889/；管理台 http://127.0.0.1:18889/admin/。两侧查询页保持一致，即使管理员已登录也仅展示查询、查看和下载；新增、编辑、删除、替换、发布/下架、恢复、导出均在登录管理台后使用。服务器仍由 Nginx 提供 HTTPS，应用端口保持回环绑定；内网 HTTPS 模板入口为 8443。
